ABSTRACT

Commercial mobile virtual assistants (e.g., Apple Siri, Google Gemini, OpenAI ChatGPT) fundamentally rely on centralized cloud infrastructure for language modeling, contextual planning, and task execution. This architectural dependence introduces a critical privacy paradox: users must transmit confidential conversations, calendar schedules, private notes, and device documents to remote third-party servers. Furthermore, cloud-dependent assistants exhibit high latency ($1.5 – 4.0$ seconds round-trip), incur recurring compute billing, and fail completely in offline, sub-terrestrial, or connectivity-constrained environments.

This Major Project presents the design, mathematical formalization, and empirical implementation of a Privacy-First, 100% Offline Mobile AI Agent capable of understanding natural language, formulating multi-step plans, and autonomously interacting with permitted smartphone APIs without network communication. The technical breakthrough addresses the 4-bit syntax collapse phenomenon: small language models ($<2\text{B}$ parameters) subjected to post-training quantization (PTQ) exhibit a catastrophic drop in JSON syntactic adherence (failing in $28\% – 42\%$ of function-calling instances), which fundamentally disables reliable agentic autonomy.

To overcome this limitation, we introduce an integrated inference architecture combining ARMv8.2-A NEON vector-accelerated C++ JNI inference with Backus-Naur Form (GBNF) Grammar-Constrained Decoding. By enforcing a finite-state machine mask directly over sampling logits, the system mathematically guarantees 100.0% syntactic validity across all tool invocations while achieving a 67.3% memory reduction (reducing model footprint from 2,460 MB in FP16 to 804 MB in GGUF Q4_K_M) and delivering a generation throughput of 28.4 tokens/second on consumer mobile processors (Snapdragon 8 Gen 2).

The mobile application is deployed via Android Jetpack Compose with a zero-internet sandbox (omitting android.permission.INTERNET at the OS manifest level), backed by an offline Room SQLite storage architecture and a dual-tier human-in-the-loop security verification gate. Empirical validation on our novel 50-task Autonomous Agent Quantization Benchmark (AAQB) demonstrates an 86.0% end-to-end task completion rate, matching full-precision cloud baselines while providing unconditional data privacy.

Keywords: On-Device AI, Small Language Models (SLMs), Large Language Model Quantization, GBNF Grammar-Constrained Decoding, Autonomous Mobile Agents, Edge Computing, Privacy-Preserving Systems, Android JNI Architecture.

Chapter 1: Introduction & Motivation

1.1 Background and Context

Recent breakthroughs in autoregressive Transformer language models have catalyzed a shift in computing, transitioning virtual assistants from rigid, command-based keyword matchers into general-purpose agentic assistants capable of multi-step reasoning, contextual planning, and autonomous execution over external tool APIs.

However, contemporary consumer deployments exclusively utilize a cloud-centric client-server paradigm. The client smartphone acts merely as a thin capture client: voice recordings, location telemetry, personal schedule queries, and file contents are continuously dispatched to remote data centers for tokenization, inference, and response generation.

1.2 The Edge Privacy Paradox

This centralized cloud paradigm introduces profound security and operational vulnerabilities:

  1. Zero-Trust Privacy Violation: Smartphones store sensitive personal information (banking details, health records, intimate conversations, and proprietary work files). Routing this data through remote third-party cloud endpoints violates zero-trust principles and exposes individuals to surveillance and centralized data breaches.
  2. Network Fragility: Mobile users frequently operate in connectivity-constrained zones (underground metros, airplanes, remote rural areas, or network outages) where cloud assistants become completely inoperable.
  3. Inference Latency: Serialization, transmission, and queueing delays across cellular networks impose round-trip response latencies exceeding $1.5$ to $4.0$ seconds.
  4. Passive Generation vs. Autonomous Execution: Cloud assistants typically return conversational text rather than reliably orchestrating local operating system APIs to perform tasks.

1.3 Proposed Solution & Scope

This project develops a complete, privacy-preserving, on-device mobile AI assistant running locally on Android smartphones. By combining 4-bit and 8-bit Post-Training Quantization (GGUF) with Backus-Naur Form (GBNF) Grammar-Constrained Decoding, the system achieves fast, reliable on-device reasoning and autonomous tool invocation under strict memory constraints ($<1.5$ GB DRAM).

Chapter 2: System Architecture & Security Design

2.1 High-Level 9-Tier Architecture

The on-device agent is structured into nine cleanly decoupled layers, operating without external internet connectivity:

[ User Interaction Layer (Jetpack Compose UI) ]
↓
[ Offline Speech-to-Text Engine (Android SpeechRecognizer / Vosk) ]
↓
[ Agent Controller & Context Budgeter (ReAct Orchestration) ]
↓
[ Native C++ JNI Inference Core (llama-bridge + ARM NEON) ]
↓
[ GBNF Grammar Logit Filter (100% Valid JSON Token Masking) ]
↓
[ Security & Confirmation Gate (Dual-Tier Policy) ]
↓
[ Tool Execution Engine (6 Core Mobile Tools) ]
↓
[ Local Storage Subsystem (Room SQLite Database) ]
↓
[ Offline Text-to-Speech Engine (Android Native TTS) ]

2.2 The Zero-Internet Sandbox Security Model

Privacy is enforced at the Android SELinux kernel boundary. The application manifest deliberately omits android.permission.INTERNET. Any socket creation syscall is blocked by the Linux kernel, preventing unauthorized network transmissions. In addition, res/xml/data_extraction_rules.xml excludes local databases and shared preferences from automated cloud backup services.

2.3 Dual-Tier Tool Safety Classification

To prevent unintended side effects, tools are strictly partitioned into autonomous and gated tiers:

Chapter 3: Implementation Details

3.1 C++ JNI Inference Engine

The native inference layer (llama-bridge.cpp) is compiled using CMake and Clang with ARMv8.2-A NEON vector flags (-march=armv8.2-a+dotprod+fp16 -O3). The engine maps quantized GGUF weights directly into memory via mmap, eliminating duplicate RAM allocations and achieving sustained generation speeds of $28.4$ tokens/second on Snapdragon 8 Gen 2 hardware.

3.2 GBNF Grammar-Constrained Decoding

To eliminate syntax collapse, the system constrains decoding using a formal GBNF grammar specification (tool_calling.gbnf): 

root ::= "{" ws "\"type\":" ws (action_payload | message_payload) ws "}"

action_payload ::= "\"action\"," ws "\"thought\":" ws string "," ws 
                   "\"tool\":" ws tool_name "," ws "\"parameters\":" ws tool_params

message_payload ::= "\"message\"," ws "\"thought\":" ws string "," ws 
                    "\"content\":" ws string

tool_name ::= "\"create_reminder\"" | "\"search_calendar\"" | 
              "\"manage_notes\"" | "\"search_local_docs\"" | 
              "\"read_document_summary\"" | "\"draft_message\""

3.3 Room SQLite Storage Architecture

The application utilizes an offline Room SQLite database with 6 tables: notes, reminders, calendar_events, documents, chat_messages, and an immutable audit_log recording all executed operations.

4.2 Analysis of the 4-Bit Syntax Collapse

The empirical evaluation demonstrates that unconstrained 4-bit quantization causes a catastrophic syntax drop ($26.0$ to $42.0$ percentage point decline), rendering autonomous agent execution unreliable. Incorporating GBNF grammar constraints restores 100.0% syntax validity, enabling an 86.0% task success rate on Llama-3.2-1B with a 67.3% reduction in memory.
