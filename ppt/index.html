Basic Concept

What is Quantization? (In Plain Words)

An everyday analogy: Imagine saving a raw 100 GB movie file as a compressed 2 GB video. It plays almost the same, but uses a fraction of storage.

ORIGINAL (FP16)

16-bit Floating Point

16 bits

Each weight is stored as a high-precision decimal number (e.g., 0.3847291...). Uses 2 full bytes of RAM per single parameter.

MEDIUM (INT8)

8-bit Quantization

8 bits

Maps the decimals into round integers between -128 and +127. Cuts memory usage by 50% (1 byte per parameter).

AGGRESSIVE (INT4)

4-bit Quantization

4 bits

Compresses weights into just 16 distinct bins (numbers 0 to 15). Cuts memory usage by 75% (only 0.5 bytes per parameter).

Full 16-Bit WeightsHigh precision, heavy RAM
→
Scaling & RoundingMap continuous float to small bins
→
4-Bit Model on DeviceRuns in 1/4th RAM footprint

Slide 4 / 13Why Quantization is Important
The Problem Statement

The Trap: The "Perplexity Illusion"

Most research papers say: "Look! The text fluency barely changed at 4-bit, so quantization is completely safe!" That is dangerously misleading.

What Common Tests Show (Fluency)

On standard WikiText, word perplexity changes from 11.2 to 12.1 (+0.9). The sentences still sound natural and fluent to humans.

What Actually Happens (Downstream Tasks)

In published literature (e.g. Jin et al., ACL 2024), when researchers test 4-bit models on multi-step reasoning or strict instruction formatting, downstream accuracy suffers a severe, disproportionate collapse!

Why Are We Doing This Project?

  • Small Models Are Fragile: Large 70B models have billions of spare parameters to cushion rounding noise. Small <2B models have zero redundancy.
  • Need a Truthful Guide: Real engineers need to know: "Can I safely use 4-bit for a chatbot? What about for a math solver?"
  • Our Goal: Test models across different task types to discover exactly when 4-bit is safe and when it breaks.

Core Hypothesis

Our Thinking: "Not All Tasks Suffer Equally"

We realized that evaluating a quantized model with one single overall score is like testing a student with only spelling questions and declaring they are good at calculus.

SIMPLE TASKS

Surface Retrieval & QA

Questions like "What is the capital of France?" or picking option A/B/C only require rough associative memory. Rounding noise has almost zero impact here.

COMPLEX TASKS

Chain-of-Thought & Rules

Solving math equations requires generating 20 sequential reasoning steps. If step 2 has a tiny rounding error, all subsequent 18 steps become completely wrong.

OUR CONCLUSION

Task-Conditioned Rules

Instead of guessing, we must build a Task-Conditioned Decision Matrix: a clear guide telling engineers the exact minimum bit-budget allowed per task class.

Technical Formulas

Parameters, Formulas & Quantization Algorithms

Basic Quantization Formula

To convert continuous weights $W$ into integers $q$, we scale and round:

q = round( W / Scale ) + ZeroPoint
W_approx = ( q - ZeroPoint ) * Scale

Error: The difference $e = W - W_{\text{approx}}$ is the quantization noise injected into every matrix multiplication.

The 4 Methods We Tested

  • FP16: Uncompressed 16-bit reference baseline.
  • BitsAndBytes INT8: Separates extreme outlier numbers (>6.0) into 16-bit to preserve critical activations.
  • BitsAndBytes NF4: Normal Float 4-bit, shapes bins according to the Gaussian bell curve of weights.
  • GPTQ: Uses second-order calculus (Hessian matrix) to adjust surrounding weights when rounding.
  • AWQ (Activation-Aware): Finds the top 1% most important weight channels by checking activations, and protects them from heavy rounding.

Statistical Methodology

Stanford HELM Calibration & Statistical Engine

UNCERTAINTY LAYER

The Calibration Problem (ECE Metric)

We incorporate the Stanford CRFM HELM formulation for Expected Calibration Error:

ECE = Σ (|B_m| / N) * |acc(B_m) - conf(B_m)|

Theoretical Vulnerability: Low-bit discretization increases logit variance, saturating softmax probabilities towards 0 or 1. Models become confidently wrong on hallucinations, bypassing safety filters.

STATISTICAL RIGOR

10,000-Iteration Bootstrap Engine

To eliminate benchmark stochastic noise and establish true significance:

  • Paired Bootstrap Algorithm: Implemented in src/metrics/statistical.py using Bias-Corrected and Accelerated (BCa) resamples (N=10,000).
  • Distribution-Free Testing: Avoids invalid Gaussian assumptions on bounded [0, 1] accuracy scores.
  • Decision Rule: Computes exact 95% Confidence Intervals for $\Delta(\text{FP16} - \text{quant})$, formally proving if degradation exceeds our $\le 3.0\text{ pp}$ safety envelope (p < 0.05).

Practical Solution

The Engineering Rulebook: Which Format When?

A clear, actionable guide for developers building AI features on edge devices:

If Your App Does... Example Use Case Safe Precision VRAM Needed Verdict
Search & Text Completion On-device search, autocomplete AWQ 4-Bit ~0.8 GB Safe (< 2 pp drop)
General Chat & Q&A Conversational customer support AWQ 4-Bit ~0.8 GB Safe (< 3 pp drop)
Strict Instruction Following Extracting structured JSON tables BitsAndBytes 8-Bit ~1.2 GB 8-bit Required
Math, Code & Multi-Step Logic Problem solvers, code generation 8-Bit or FP16 ~1.2 – 2.5 GB Never use 4-bit
The Golden Rule: For simple recall and chatbots, 4-bit AWQ saves huge memory with zero noticeable downside. But the moment an app requires multi-step logic or strict JSON schema, you must stay at 8-bit.
